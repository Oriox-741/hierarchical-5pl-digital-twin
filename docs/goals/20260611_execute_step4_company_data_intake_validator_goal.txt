Primary key rules:
- orders: order_id
- dispatch_attempts: dispatch_attempt_id
- deliveries: dispatch_attempt_id
- routes: route_id
- fleet: vehicle_id
- inventory: sku_id + site_id + order_id
- costs: order_id

Join-key rules:
- order_id must exist in orders, dispatch_attempts, deliveries, routes, inventory, and costs.
- dispatch_attempts.order_id must exist in orders.order_id.
- deliveries.order_id and deliveries.dispatch_attempt_id must match orders and dispatch_attempts.
- routes.order_id must exist in orders.
- dispatch_attempts.route_id must exist in routes.route_id.
- dispatch_attempts.vehicle_id must exist in fleet.vehicle_id.
- dispatch_attempts.carrier_id should exist in fleet.carrier_id; if vehicle_id joins, carrier-only mismatch may be warning.
- inventory.order_id must exist in orders.
- inventory.sku_id and inventory.site_id must be present where inventory validation is claimed.
- timestamps must have shared semantics and should prefer ISO-8601 UTC strings ending in Z or explicit offsets.

Data-quality rules:
- Required columns present for each table.
- Required timestamps parse.
- promised_window_start <= promised_window_end.
- If present, decision_timestamp <= pickup_timestamp <= delivery_timestamp.
- If present, dispatch_attempt_timestamp <= pickup_timestamp.
- Costs are non-negative.
- Route distance, travel time, vehicle capacity, and inventory quantities are non-negative.
- fleet_type is primary or secondary.
- reorder_type is none, conservative, aggressive, or emergency when present and non-empty.
- action_id is an integer in 0..47.
- No duplicate primary keys.
- Empty optional fields do not block readiness.

Output schema:
Top-level JSON keys:
- report_metadata
- table_summaries
- join_key_checks
- data_quality_checks
- warnings
- decision

Decision classifications:
- COMPANY_DATA_SCHEMA_READY
- COMPANY_DATA_SCHEMA_WARNINGS_ONLY
- COMPANY_DATA_SCHEMA_NEEDS_FIXES
- COMPANY_DATA_SCHEMA_BLOCKED

Classification priority:
1. Missing required table or unreadable fixture -> COMPANY_DATA_SCHEMA_BLOCKED.
2. Missing required columns, duplicate primary keys, malformed required timestamps, impossible required ordering, invalid controlled labels, invalid action id, or required join failure -> COMPANY_DATA_SCHEMA_NEEDS_FIXES.
3. Missing optional fields, carrier-only warning where vehicle joins, or timezone-naive parseable timestamps -> COMPANY_DATA_SCHEMA_WARNINGS_ONLY.
4. All required schemas, joins, timestamps, labels, and non-negative constraints pass -> COMPANY_DATA_SCHEMA_READY.

Synthetic fixtures:
- valid_minimal: one valid row per table, all required joins present, fleet_type secondary, reorder_type none if included, non-negative costs, UTC timestamps, action_id in 0..47.
- missing_required_columns: remove promised_window_end from orders and dispatch_attempt_id from dispatch_attempts.
- bad_timestamps: unparsable created_at plus promised_window_start after promised_window_end.
- duplicate_keys: duplicate orders.order_id and dispatch_attempts.dispatch_attempt_id.
- invalid_labels: fleet_type overflow_unknown and reorder_type delay_forever.
